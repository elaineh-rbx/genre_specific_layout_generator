# Scene prompt
Create a 3D ball-maze map as a single compact handheld wooden puzzle tray, with raised wooden walls forming one plainly playable labyrinth from a starting area to a visible exit.

# Agent decision
## Genre
The genre is Puzzle: the player tilts a physical maze so a ball can traverse from start to exit.

## Shape and preset
Use `puzzle-maze` because the solvable labyrinth topology is the activity even though an avatar does not walk through it. The preset is Maze / Labyrinth, with collectible items omitted and no extra loop requirement added.

## Config requirements
The image config needs one compact rectangular wooden tray, a recessed maze floor, raised wooden labyrinth walls, a clearly differentiated ball starting pocket, and one visible exit pocket. These are scene-specific geometry; no buttons, clue walls, item sockets, or progression gates are requested.

## Layout requirements
Place one ball spawn marker in the starting pocket and one completion trigger inside the sole exit pocket. The ball must fit every corridor with movement clearance and must have one continuous valid route from start to exit. Nothing is placed for avatar traversal because the player operates the tray through phone tilt.

## Layout components
Build a single handheld-scale wooden puzzle tray with a solid outer rim and one compact maze carved or assembled inside it. Raised partitions form the labyrinth on one flat recessed floor. Put the starting pocket and visible exit in well-separated regions, maintain continuous corridors between them, and prevent gaps through the outer rim. Keep the whole tray isolated against a simple neutral display background and compose it in frame from a high angle so the complete maze is readable.

## Render order
Render `authored_plan` first and treat its computed blueprint as authoritative, then create the top-down and isometric views from it. A maze generator must guarantee that the ball can reach the exit.

## Scale, theme, and pipeline cost
Scale is small, defined by one handheld tray. The theme is a classic polished wooden tabletop puzzle. Use `P6` for valid maze construction and `SET` because no avatar walks through the real 3D geometry, so traversal and jump-gap checks are skipped.
