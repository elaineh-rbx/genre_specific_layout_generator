# Agent decision

## Clarifications resolved
- [author] scale — Q: How tall is one generated segment before it repeats? An endless tower has to be built as a repeating chunk rather than one map. A: Use small repeating vertical segments, about 100 studs tall each, so the tower can keep generating above the player without needing a huge map.
- [author] goal — Q: If the climb never ends, is there anything to chase - a height record, a leaderboard - or is the height itself the whole game? A: Add a height record and a simple leaderboard; the goal is to climb as high as possible.
- [agent_inferred] fall recovery — Q: What does “try again from the place you landed on” mean when a player falls into empty space? A: Respawn at the most recently reached stable landing platform, with at least one safe recovery point in every generated segment.

## Enriched image prompt
Create an endless colorful parkour tower assembled from repeating vertical modules about 100 studs tall. Each module continues upward from the one below through a valid sequence of increasingly difficult platforms, with its top connection aligned to the next module’s base. Mix wallhop sections, staircases that disappear after being stepped on, kill-brick hazards, and varied climb obstacles, while preserving stable landing platforms for recovery. Use bright changing colors to distinguish generated sections and make the ascent visibly harder with height. Place a simple height leaderboard at the tower base, but do not create a summit or terminal reward area because the climb never ends.

## Genre
The dominant genre is Obby & Platformer, canonical slug `obby-platformer`.

## Shape and preset
Use `course-tower`, Tower / Spiral Ascent with generated platform sections stacked overhead. The matched preset is Tower Obby, retaining its sequential track, timed obstacles, and climb obstacles while dropping its terminal winner zone because this course is endless.

## Config requirements
Use `chunk-modular`, taken from the shared catalogue, for aligned 100-stud vertical modules; `path-track` for each upward platform chain; `obstacle-climb` for wallhops and climbing sections; `obstacle-timing` for disappearing staircases; `hazard-kill` for kill bricks; `checkpoint-respawn` for visible stable recovery landings; and `tracker-leaderboard` for the base height board.

## Layout requirements
Place at least one `checkpoint-respawn` Checkpoint on a stable landing in every 100-stud module. Place one `tracker-leaderboard` Tracker at the tower base. Place one `trigger-despawn` TriggerZone several completed modules below the active player to recycle old tower geometry. No finish or winner placement is allowed.

## Layout components
The build has a base lobby and an unbounded stack of approximately 100-stud modules. Every module has matching entry and exit anchors, a connected upward route, timed stairs, lethal bricks, climb obstacles, and a safe recovery landing. Wallhop sections are author-required but cannot be validated against documented movement physics.

## Render order
Use `topdown`; each module’s route and vertical joins must be valid before colorful tower dressing, with separate captures for overlapping levels.

## Scale, theme, and pipeline cost
Scale is medium per 100-stud module even though the generated tower is endless. The theme is bright, colorful escalating parkour. Use `P6` for valid module joins and ordinary obstacle spacing, and `P2` because stacked modules overhang one another.
